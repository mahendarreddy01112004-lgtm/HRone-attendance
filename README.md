# REVIEW.md

I read the starter app/main.py as if a teammate had sent it as a pull request. These are the defects I found, helpers first and then the endpoints. Everything below is fixed in my version.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | compute_late_minutes | It floors to whole minutes first and then checks "greater than 10", so 10 minutes and 1 second becomes 10 and is thrown away. | Shift 09:30, punch in at 09:40:01. The rule says 10, the starter returns 0. | Compare in seconds (more than 600 seconds late), then floor to whole minutes. |
| 2 | compute_late_minutes | The shift start is built from the punch-in's own date with no IST handling. For an overnight shift, a punch-in after midnight is measured against the wrong evening. | Shift 22:00 to 06:00, punch in at 05:30 next morning. The start should be the previous evening at 22:00 but the starter uses 22:00 of the same day. The result is wrong, and also wrong if the server is not in India. | shift_window builds the start and end in IST from the record's attendance date, and moves the end to the next day for overnight shifts. |
| 3 | compute_work_hours | It uses Python round() on a float. The rule asks for half-up with 2 decimals, and round() gives a different answer for exact halves. | A work time of 3618 seconds is exactly 1.005 hours. The starter gives 1.0 and the rule says 1.01. | Use Decimal and ROUND_HALF_UP on seconds divided by 3600. |
| 4 | compute_overtime | There is no 30 minute minimum. It also subtracts a naive datetime from a time zone aware one, which raises a TypeError, and the end of an overnight shift stays on the same day. | Punch out 10 minutes after shift end: the starter says 10, the rule says 0. As soon as it is called it crashes with a 500. | Rewritten on top of shift_window, floor to whole minutes, and return 0 when below 30. |
| 5 | MongoClient setup | The client is created without tz_aware, so PyMongo hands back naive datetimes that are easy to mix with aware ones. | created_at in GET /employees came back as a text date with no time zone. | tz_aware=True, plus ms_to_dt and dt_to_ms to convert at the edge of the API. |
| 6 | create_employee | It checks for a duplicate with find_one and then inserts. Two requests at the same moment both pass the check. There is no unique index either. | Send the same new emp_code twice in parallel and two documents are stored. | Unique index on emp_code created at startup, insert directly, and turn DuplicateKeyError into 409. |
| 7 | create_employee / EmployeeIn | There is no validation, so a bad emp_code, a bad email, a shift time like 25:99, an impossible date or shift_start equal to shift_end are all accepted. | POST emp_code "abc", shift_start "25:99", joined_on "2026-02-31" and get 201. | Pydantic patterns and validators, so these return 422. |
| 8 | create_employee | created_at uses datetime.now(), which is the server's local time with no zone, and the response returns it as text instead of epoch milliseconds. | created_at shows as a text date in the response. | Store a UTC datetime cut to whole seconds and return milliseconds through employee_out. |
| 9 | list_employees | The offset is page * page_size, so page 1 skips the first 20 records. | With 6 employees, GET /employees shows total 6 but an empty items list. | skip = (page - 1) * page_size. |
| 10 | list_employees | total counts every employee even when a department filter is used, there is no sort, and page and page_size are not validated. | department=Sales shows total 6 but only 2 match. page=-1 gives a negative skip and a 500. page_size=100000 is accepted. | count_documents on the same filter, sort by emp_code, and Query limits (page at least 1, page_size from 1 to 100). |
| 11 | punch_in | The employee is never checked, so an unknown emp_code makes emp["shift_start"] fail with a TypeError. | POST punch-in with emp_code EMP9999 and get a 500. | Return 404 when the employee does not exist. |
| 12 | punch_in | It uses datetime.fromtimestamp(ms / 1000), which takes the server's local time zone and keeps the milliseconds. The date comes from that local time instead of IST, and there is no overnight rule. | Run the server outside India, or punch in at 01:00 IST, and the date is wrong. An overnight employee punching in at 05:30 gets the wrong day. | ms_to_dt gives a UTC time cut to whole seconds, and attendance_date applies the IST date and the overnight rule. |
| 13 | punch_in | It does find_one and then insert_one, so two identical punch-ins at the same moment can both pass the check. | Send two requests in parallel and get two 201 responses. | Unique index on (emp_code, date) and turn DuplicateKeyError into 409. |
| 14 | punch_in / PunchInIn | status is any string, punched_at is any number, and the check "if body.punched_at" treats 0 as missing and quietly uses the current time. | status "BANANA" or "ABSENT", a timestamp in seconds, a negative number or 0 all give 201. | status is limited to PRESENT, WFH and ON_DUTY, punched_at is a strict integer in the epoch millisecond range, and anything else is a 422. |
| 15 | punch_in response | The response has an extra "id" field with the ObjectId text and raw datetimes, but _id must never appear and instants must be milliseconds. | The response contains "id": "65f..." and punch_in as a text date. | attendance_out builds the response field by field. |
| 16 | list_attendance | It loads every matching document into Python and sorts and slices there, which is slow and memory hungry at 100,000 records. It sorts by date only with no emp_code tie break, does not validate status or dates, and leaks "id". | Call GET /attendance on a large collection and it gets slow. Equal dates come back in an unstable order. | Filter, sort, skip and limit inside MongoDB, with count_documents for total. Indexes on (date desc, emp_code) and (status, date desc, emp_code). Typed date and status parameters, and 422 when date_from is after date_to. |
| 17 | health | It always returns ok, even when MongoDB is down. | Stop MongoDB and /health still returns 200. | Ping MongoDB and return 503 if it fails. |
| 18 | whole app | No indexes are created, so every query would scan the whole collection. | The explain output would show COLLSCAN. | ensure_indexes runs at startup and can be run any number of times. |

## Things I looked at and decided were not defects

- load_dotenv() does not overwrite variables that are already set, so real environment variables win over the .env file, which is what the contract asks for.
- Comparing dates as strings with $gte and $lte in list_attendance is fine. YYYY-MM-DD strings sort in calendar order, and DATA_MODEL.md says dates are stored as strings on purpose.
- IST = UTC+05:30 is correct and India has no daylight saving, so a fixed offset is safe.
- Returning 201 on create and 409 for a duplicate are the right status codes. The idea was right, only the way it was done was open to a race.
- doc.pop("_id", None) after insert_one was needed because insert_one adds an ObjectId. It works, but I replaced it with an explicit response builder.
